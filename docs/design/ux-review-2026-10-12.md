# reppit UX review, 2026-10-12

Reviewed: the tour4 screenshots (16 screens, desktop 1440 and phone 390) and the live site at localhost:3100, read only. I checked computed styles with Playwright to confirm leftovers. Selectors refer to `apps/web/app/globals.css` (base) and `apps/web/app/skin.css` (the new GitHub skin that loads after it).

## 1. Verdict

The restyle mostly works. The masthead, the blue owner/name links, the pill chips, the green primary button and the white cards on `#f6f8fa` read as GitHub straight away. The vote rail plus the About sidebar read as Reddit. On the home feed and search results it no longer looks AI-generated.

It still feels generated in three places:

- **The copy.** Most paragraphs are knowing, defensive asides, such as "If every vote on reppit vanished tonight…", "we are not going to pad it out…", "It is the question nobody else asks." and "This is a first-class screen, not an export." This voice is the main thing that still reads as AI.
- **Half-finished skin seams.** The item page, trust page, account page and agent page still carry the old system: uppercase tracked labels, monospace links, rust focus boxes, blue meter bars and a near-black terminal page.
- **A feed where every row looks the same.** About 25 of the 30 home rows show "93/100, 5 of 6 measured", with "—" where a vote count should be.

Would I use it? For one question, yes: search "parse command line arguments in rust", get clap, 93, pushed 5 days ago, with `cargo add clap` ready to copy. That answers the core problem in about 5 seconds, and it is genuinely better than stars.

A first-time visitor on the home page does not get there in under 10 seconds:

- They see two search boxes.
- They see a coloured legend they have to decode.
- They see a "Hot" feed of SDKs that all score 93, so nothing stands out.
- Search misses common needs. "retry with exponential backoff python" returns nothing, even though tenacity is the obvious answer.
- Skills, half the pitch, all show "too little measured".

The design is now close to familiar. The remaining work is mostly about clearer meaning: show why a score differs, say less, and make every surface use the same tokens.

## 3. Brand consistency

**Colours.** The skin has two primary action colours: rust (`#d93900`) for Search and green (`#1f883d`) for Join, Sign in, Submit and Create account. GitHub uses green for "do it" and nothing else loud. Recommendation: Search stays rust, because it's the brand's one hero action and pairs with the logo, but no other control uses rust (fix #15). Status colours need to be one set everywhere: holds green `--green-ink`, slipping `--amber`, failing `#cf222e`. They currently split three ways: the feed strip is green, the item `.pbar` is blue, and the trust page legend says blue and rust (fixes #11 and #12). Promote `#cf222e` to a token `--red` in all three `:root` blocks; it is hard-coded in `.strip i.bad`.

**Logo mark.** An orange circle with a white up-triangle drawn with CSS borders (`.logo i::after`). It reads clearly as "upvote" and is distinct enough from Reddit's Snoo. Two problems:

- It's built from borders with magic offsets (`left:7px;top:6px`), so it sits slightly off-centre at 26px and won't scale. Ship it as an SVG in `components/marks.tsx` and use the same SVG for the favicon.
- On phone it is the same size as desktop, but the wordmark is 20px bold with `letter-spacing:-.03em`. That's fine; keep it.

**Type.** The sans stack is now global, but these spots are still monospace:

- `.kv-link.mono`: the "Measured, not voted" / "Considered instead" repo links on the item page. Remove the `mono` class in `Item.tsx`.
- `.fld select` (globals line ~578): the agent and result selects on the compat form.
- `.theme button`, `.cmd .copy` ("copy"), `.tools code` (fine, it's code), `.compat-h`, `.report .who`, `.rrow .t`, `.arg h3`, `.pull p`. Most are covered by the skin's big selector list, but `.fld select`, `.kv-link.mono`, `.theme button` and `.cmd .copy` render mono in the live DOM. Add them to the skin's sans list.
- Terminal page: entirely mono. This is intended, but see fix #10.

**Uppercase or tracked labels still live:**

- `.score-hero .big s` / `.cold .big s` ("TRUST · 2 OF 4 MEASURED")
- `.panel-h .lbl` with inline `.1em` tracking (4 places)
- `.flag` ("SLOWING", "LICENCE UNCLEAR"): globals sets `text-transform:uppercase;letter-spacing:.06em` and the skin does not reset it. Add `.flag{text-transform:none;letter-spacing:normal}` and write the copy as "Slowing" and "Licence unclear".
- `.evidence .ex-lbl` at 9.5px

**Rust leftovers:** `::selection{background:var(--rust)}` (the skin overrides it, good). `.linkish`, `.required`, `.required.as-btn`, `.btn[aria-disabled]`, `.vote-msg`, `.rail-err`, `.auth-msg.bad`, `.check input` accent, `.state .lbl` and `.cmd-docs .docs-link` (the skin overrides it, good). Also the terminal palette `--t-rust`, `.tbar i.on` and `.cursor`. Errors should use `--red`, not rust, so the brand colour never means "wrong".

**Buttons.** Primary is green, secondary is grey-bordered, and Search is a rust pill. Pills (`999px`) appear on Search, chips and sorts, while `6px` corners appear on buttons and cards. That matches GitHub. The odd ones out:

- The item `.votebar` is square-cornered and segmented.
- The "copy" button is 11px mono.
- "Submit downvote" is a rust outline.

Make all three `.btn .btn-sm`.

**Chips.** Language and licence chips are identical blue pills (`.tag.plain`). Licence isn't a topic, so GitHub shows it as plain text with an icon. Change it to `.tag.licence{background:transparent;color:var(--ink-3);padding:0}` with a ⚖ icon. Then language stays the only blue pill and the warning flags (amber outline) stand out. Item page chips such as "487k stars", "no release data" and "added to reppit 4 days ago" are all the same blue pill even though they're facts, not tags. Render them as a `.meta` line separated by `·`.

**Copy tone.** Two voices sit side by side: a crisp GitHub voice ("Sign in", "Submit a repo", "Your votes") and a self-aware essay voice ("we are not going to pad it out", "the question nobody else asks", "This is a first-class screen"). The second voice is what makes it feel generated. Rule: one sentence per paragraph where possible, no talking about what the page refuses to do, and no addressing the reader's scepticism. The lines are in §4.
